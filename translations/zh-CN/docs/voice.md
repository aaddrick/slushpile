第八个智能体负责写求职信，而且它按某一个具体的人的风格来写，这个风格是从那个人自己写的东西里建出来的语料上做出来的。

这是这条流水线里唯一需要你自己带来的部分。

## 为什么要一个单独的智能体

求职信是一份申请材料里唯一应该听起来像个人的文档。一个模型"用你的文风"从简历出发写出来的，是模型的默认腔调加上你的事实——称职、统一，而且当天的第六十一位读者一眼就认得出来。

所以文风不是一条 prompt 指令。它是一份智能体定义，由你几千字的真实文字生成，在一组文体维度上被测量过，带着后续检查可以对照的数值目标。

## 生成你自己的

[written-voice-replication](https://github.com/aaddrick/written-voice-replication)
是一条你跑一次就够的独立流水线。它在 25 个维度上分析你的写作语料，输出一个文风智能体、一个文风技能，以及一份带可测量目标的数值画像。

攒语料是慢的那一步，所以在你需要它之前就开始攒。

**好的来源：** 论坛和 Reddit 帖子、博客文章、长的 Slack 消息、写给同事的邮件、pull request 描述、你独自写成的文档。Reddit 或 Twitter 的数据导出可以直接用。

**坏的来源：** 任何合写的、任何被别人编辑过的、任何已经过了一遍 LLM 的、任何用机构口吻写的。营销文案和绩效评语是最糟的两种——两者都写在一种没人会自愿使用的腔调里。

几千字是下限。低于这个数，输出读起来就是泛泛的，而这是最难被察觉的失败模式，因为它看上去是完成了的。

## 让 slushpile 指向它

```yaml
voice:
  agent: "your-name-voice"
  is_mine: true
```

`voice.agent` 按名字指定这个智能体，没有任何地方把它写死，这就是你能换成自己的而不用改插件的原因。

## 在那之前

`aaddrick-voice` 作为一个能用的示例随插件发布，好让流水线开箱就能跑。它是插件作者的文风，不是你的。用它写出来的信会听起来像某个具体的陌生人——用来看看流水线怎么运转没问题，用在你真要寄出去的东西上就是错的。

只要 `is_mine` 是 false，每一个会起草文字的技能都会在运行前警告你。那条警告是唯一挡在你和十二份以陌生人文风寄出去的申请之间的东西，所以在这个智能体真正属于你之前，别把标志位设成 true 把它关掉。

## 文风怎么被使用，又怎么被守住

`/slushpile:removing-ai-tells` 让求职信过一遍全新的文风智能体实例，由编排它的技能对每一处单独改动充当守门人。一遍照单全收所有建议的处理，会把这封信重新磨回平均值，而这正是文风智能体存在要防止的事。

审阅里那个疲惫的读者会被拿去对照你的文风智能体，理由相同。在那里被记录下来的一个鲜明习惯，不会因为某个角色标了它就变成缺陷，而删掉它恰恰就是一封信滑回泛泛之作的方式。

要注意，文风智能体按其构造就是某一个人的身份——由他们写的东西生成、以他们命名，示例是他们真实的句子。这就是为什么它是本仓库里唯一豁免于约束其他一切的个人数据规则的智能体，也是为什么这项豁免到联系方式为止。见 [智能体与模型](architecture/agents-and-models.md)。
